# Milestone 2 eval: repair, traces and a stricter deadline

Run on 2026-10-03 with `GEMINI_MODEL=gemini-3.5-flash-lite NVIDIA_API_KEY= npm run eval -- --name 2026-10-03-m2`
on the milestone 2 working tree as handed over (not yet committed). Same settings
as the M1 run in `2026-10-03-m1.md`: `gemini-3.5-flash-lite` writes the plan, with
`gemini-3.1-flash-lite` as fallback. The NVIDIA panel was off this time; in M1 it
was on, but every call returned 410 in about 0.1s, so the comparison holds.

New in milestone 2:
- **Repair.** After the first map pass, one request asks for the OpenStreetMap
  name of each place not found: `gemini-3.1-flash-lite` first, then
  `gemini-3.5-flash-lite` if the first takes over 4.5s or fails. Only new names
  are searched, and a hit counts only if one of OSM's names for it contains every
  word of the proposed name.
- **Traces.** Every record carries the request's trace, and stage times come
  from it.

## How this run came about

This is the third M2 run. The first two each found a problem, fixed before this
one (D19 and D20 in `docs/upgrade-plan.md`):

1. **Repair on one model only** (stopped after 14 cases). `gemini-3.1-flash-lite`
   was overloaded at the time, and repair timed out in 5 of 12 plans. The fix: a
   second model after 4.5s.
2. **Before the name check** (all 24 cases). Repair found 12 places, but a manual
   review showed one wrong pin: "Làng hoa Ngọc Hà" matched a community centre in
   the next province. The fix: the name check.
